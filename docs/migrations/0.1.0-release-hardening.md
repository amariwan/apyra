# 0.1.0 release-hardening schema upgrade

This upgrade adds worker ownership and optimistic-concurrency fields to existing outbox and
workflow tables. It is an additive migration for databases created before the P3–P7 release
hardening changes.

## Before applying

1. Take and verify a database backup.
2. Stop all Apyra outbox dispatchers and workflow workers; do not run old and new workers together.
3. Confirm both tables exist. This migration does not create either table or modify application
   data.
4. Apply the script exactly once with a database account that can alter these tables and create
   indexes. Database products with transactional DDL should run it in a transaction. MySQL may
   commit DDL statements individually; keep the backup and complete the remaining statements before
   starting the new application version.

## Apply

Use [`sql/0.1.0-release-hardening.sql`](sql/0.1.0-release-hardening.sql) with the database's
native client or your migration system. Its `ALTER TABLE` and `CREATE INDEX` statements are
supported by PostgreSQL, MySQL, and SQLite versions that support `ALTER TABLE ... ADD COLUMN`.

For installations using `PostgresIdempotencyStore`, also apply the PostgreSQL-only
[`sql/0.1.0-postgres-idempotency.sql`](sql/0.1.0-postgres-idempotency.sql). It creates the
idempotency table introduced by this release. Do not apply it to MySQL or SQLite; the
PostgreSQL-backed store is not supported on those databases.

The new `version_id` values start at zero for existing rows. Ownership fields start as `NULL`; any
in-flight leases must be drained before migration so no worker relies on the old lease state.
Indexes are added for outbox polling and lease recovery.

After applying, verify the three new columns on both tables and both named outbox indexes. If
PostgreSQL idempotency is enabled, also verify `apyra_idempotency` exists. Complete these checks
before starting upgraded workers. The PostgreSQL integration test
`tests/integration/test_release_schema_migration.py` applies these exact scripts to pre-upgrade
table definitions and checks that existing rows remain readable.

## Rollback

Stop all upgraded workers before rolling back application code. The added columns and indexes are
not required by the prior version. Drop `ix_apyra_outbox_poll` and `ix_apyra_outbox_lease`, then
drop `leased_by`, `fencing_token`, and `version_id` from both tables using the database's DDL
dialect. This discards lease ownership and concurrency counters written after upgrade; restore the
backup instead if those values are needed for recovery. If the PostgreSQL idempotency script was
applied, dropping `apyra_idempotency` discards its deduplication records; restore the backup if that
state is needed to prevent duplicate processing.
